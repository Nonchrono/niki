## 남은 위험과 배포 판단

1. **높음 — 저장 파일과 백업은 평문이다.** `journal.json`, `media/`, Documents의 자체 JSON 백업에 일기와 첨부가 암호화 없이 저장된다. 화면 잠금은 같은 사용자 권한의 프로그램, 파일 접근 권한이 있는 사람, 백업 폴더의 동기화 서비스를 막지 못한다. UI에서 백업 전에 이 사실을 알리지만 기밀성 위험 자체는 해결되지 않았다. 민감한 일기용 보안 앱으로 배포하려면 인증 암호화를 적용하고 기존 평문 파일을 안전하게 이전해야 한다.
2. **중간 — 대용량 가져오기는 메모리를 많이 쓴다.** ZIP 해제 결과는 파일당 100 MiB, 총 250 MiB로 제한하지만, base64 입력·JSON 파싱·백업 미디어 복제가 동시에 메모리에 존재할 수 있다. 공격자가 제공한 큰 백업은 앱을 느리게 하거나 종료시킬 수 있다. 스트리밍 가져오기와 항목 수·중첩 깊이 제한이 필요하다.
3. **중간 — 앱 잠금은 보조 보호다.** Argon2 해시를 사용하지만 로그인 시도 횟수 제한이 없고 데이터는 이미 평문이다. 잠금 암호를 기밀성 보장으로 안내해서는 안 된다.
4. **검증 미완료 — 의존성 취약점 목록.** `Cargo.lock`으로 버전이 고정되어 있으나 현재 환경에는 `cargo-audit`이 없어 RustSec 전체 권고와의 대조를 완료하지 못했다. 배포 전 최신 RustSec 검사, WebView2 런타임 업데이트, 서명된 설치 프로그램 검증이 필요하다.
5. **Google Drive 동기화는 미완성이다.** OAuth 연결을 시험하는 화면과 암호화·전송 구성 요소가 추가됐지만 실제 Google 계정으로 검증되지 않았고 동기화 엔진에 연결되지 않았다. 실제 클라우드 데이터 경로와 권한 설정의 안전성은 검증되지 않았다. [설계 문서](GOOGLE_DRIVE_DESIGN.md)의 보안 조건과 두 기기·오프라인·충돌·손상된 암호문 테스트가 필요하다.

현재 앱은 로컬 기능 평가용으로 사용하고, 민감한 기록을 다루는 배포는 평문 저장 문제를 해결한 뒤 진행하는 것이 안전하다.
